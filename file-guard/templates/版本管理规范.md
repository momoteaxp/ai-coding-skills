# {project_name} 版本管理规范

> 由 FileGuard 骨架生成；规则与 FileGuard 套件 `docs/版本管理规范.md` 一致。
> 修改本文件需经用户确认。

## 一、版本号格式

- 三段式 SemVer：`X.Y.Z`（主版本.次版本.修订）
- 版本单一来源：`project_meta.json` 的 `version` 字段；`docs/README.md` 顶部版本行随其同步

## 二、递进规则

| 位 | 触发条件 | 示例 |
|---|---|---|
| 主版本 X | 破坏性变更 / 架构重构 / 不兼容升级 | v1.0.0 → v2.0.0 |
| 次版本 Y | 新增功能、新增目录类型、新增工具 | v0.1.0 → v0.2.0 |
| 修订 Z | Bug 修复、文档修订、不改变行为的调整 | v0.1.0 → v0.1.1 |

## 三、发版纪律

1. 改版本号 = 必须发版：git tag + release 归档，保持 meta/release/tag 三者同步
2. 发版前工作树必须 clean；发版后校验 zip 完整性与核心文件齐全
3. 禁止"版本号已变但 release 缺失"的状态存在

## 四、回滚规则

- 误发版：从 `release/` 或 `archive/` 取上一版本包，恢复 meta 版本号并重新发版
- 数据误删：`_trash\` 30 天内可恢复；Git 可 `git checkout` 恢复已提交内容
